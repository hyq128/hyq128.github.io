# 页面内容与素材维护

本指南说明如何持续扩展个人网站内容，同时保持招聘者容易浏览、内容真实且结构清晰。

## 页面区块

所有页面内容都在 `public/index.html`。主要区块按当前页面顺序排列：

1. `#about`：姓名下方展示产品经理与项目经理两个英文求职方向；先展示人工智能本科及金融科技硕士教育背景，再展示跨行业经历和实际工作中的 AI 使用。经历文字中的公司名称链接到对应公司介绍。宽屏时介绍在左、头像在右；窄屏时介绍在上、头像在下，并保留关注方向标签。
2. `#internships`：页面标题为“经历”，保留此锚点以兼容已有链接。按开始时间由近到远放入两段教育和四段实习，构成整屏吸顶的 360° 3D 环形画廊。页面滚动驱动六张图文卡片旋转，停止滚动后缓慢自转；底部轻量“成长轨迹”与正面卡片同步，当前节点显示完整日期和职位，其余节点显示起始年月及学校或公司。时间轴支持点击和键盘导航，手机端可横向滑动。新增经历时同步更新卡片、时间轴节点、顺序和图片，并检查圆环角度与移动端排版。
3. `#ai-work`：AI 辅助解决实际问题并形成工具或小产品的案例。案例准备好后，说明问题背景、AI 如何参与、个人完成的工作和可观察的结果；没有真实案例时保留“整理中”状态，不要编造项目或效果。
4. `#projects`：相对完整的产品项目，说明项目背景、个人角色、行动、结果和可公开的链接。AI 相关效率工具可放在 AI 作品区；完整产品项目仍可放在项目区，并明确两者的展示重点。
5. `#articles`：已发布文章或复盘。暂时没有文章时使用简短的整理中提示，不保留虚构标题、日期或链接。
6. `#contact`：公开主页链接和用户愿意公开的社交账号。

新增、移除或重排区块时，为区块保留唯一 `id`，同步更新主导航、README 和本指南。区块的序号应与实际顺序一致。

## 照片

- 将个人照片放在 `public/assets/photos/`。
- 在 HTML 中从 `public/index.html` 使用相对路径引用，例如：

  ```html
  <img src="./assets/photos/portrait.webp" alt="在海边散步的我" />
  ```

- 优先使用 WebP、JPEG 或 PNG。裁切到适合版面的尺寸，避免提交不必要的超大原图。
- 经历卡片上方为照片，下方为日期、学校或公司、专业或职位，以及一句真实的补充信息。照片底部以小范围渐隐模糊过渡到暖白信息区，避免遮住主体或影响文字清晰度。顶部标签统一写为“教育”或“实习”：教育卡片使用灰紫标签，实习卡片使用粉色标签；具体学历和岗位写在下方信息区。通过图片的 `object-position` 调整裁切焦点，替换照片后检查桌面端、手机端的人像焦点和信息区高度。
- 港中深原始照片虽以 `.jpg` 命名，实际是 HEIF 格式；网页引用已转为 JPEG 的轻量 `cuhksz-card.jpg`。华师网页照片为去除相机元数据的 `scnu-card.jpg`。替换时继续使用浏览器兼容的轻量副本。
- 每张有信息的图片都应提供准确简短的 `alt` 文本；纯装饰图片使用空 `alt` 或通过 CSS 绘制。
- 只使用自己拍摄、拥有授权或许可公开的图片。不要把隐私照片或他人信息未经许可发布到公开网站。

## 内容准确性与隐私

- 日期、职责、数据和结果以本人提供的简历或项目材料为准。没有来源支持时不要增加数字或夸大个人贡献。
- 只填写愿意公开的联系方式。手机号、私人邮箱等信息只有在用户明确要求公开时才放入页面。前端 HTML 和 JavaScript 会被网站访客读取。
- 简历附件可能含有私人信息；除非用户明确要求提供下载，不要把整份简历复制到 `public/`。
- 不要提交 API Key、密码、访问令牌、私钥或 `.env` 文件。

## 样式与维护

- 全站样式和断点在 `public/css/styles.css`；交互在 `public/js/main.js`。
- 沿用 CSS 自定义属性和现有组件规则。新内容应保持奶油白、柔和粉色强调、清晰的中文衬线标题及易读的无衬线导航，同时检查桌面和窄屏布局、键盘焦点与减少动态效果设置。
- 新增文章或项目时复制真实内容的区块结构，替换所有标题、日期、摘要、图片替代文本和链接；删除不再准确的内容。
- 代码或内容变化后检查 README、本指南、`AGENTS.md` 和 `docs/WORKFLOW.md` 是否仍准确，并在 `CHANGELOG.md` 记录对应变更。提交规范见 [`docs/WORKFLOW.md`](WORKFLOW.md)。
